# Close to tray and restore from the tray icon

- Status: done
- Date: 2026-11-15
- Areas: `crates/steamtron-desktop/src/main.rs`, `crates/steamtron-desktop/Cargo.toml`

## Problem

Closing the SteamTron window exits the application. There is no tray icon,
so a background Steam/library session cannot be kept alive and restored
quickly.

## Goal

Closing the window hides it to the system tray instead of exiting. A single
left click on the tray icon shows and focuses SteamTron. Right click opens a
menu with **Show SteamTron** and **Quit SteamTron**.

## Non-goals

- Starting a second instance when the desktop launcher is clicked again.
- Changing the in-app dialog or navigation behavior.
- Auto-starting SteamTron on login.
- Native tray integration on non-Linux platforms in this change.

## Requirements

- R1: On Linux, the main window's close request is prevented and the window is
  hidden; the process keeps running.
- R2: A StatusNotifier tray icon is created at startup using the application
  icon.
- R3: A single left click on the tray icon shows, unminimizes, and focuses the
  main window.
- R4: Right click opens a tray menu with Show SteamTron and Quit SteamTron.
- R5: The menu's Show entry restores the window; Quit exits the process.
- R6: The tray uses `ksni` directly, so the build and runtime do not require
  libappindicator or Tauri's tray feature.

## Acceptance criteria

- [x] Closing the window leaves the process running with a tray icon.
- [x] Left click on the tray icon restores and focuses the window.
- [x] Right click offers Show SteamTron and Quit SteamTron.
- [x] Quit exits the application.
- [x] The release build links and starts without libappindicator installed.

## Decisions and risks

- Tauri's `tray-icon` feature is not enabled: the Tauri CLI refuses to bundle
  when no appindicator library is installed, even though the ksni backend does
  not need it. The Linux tray is implemented directly with `ksni` instead.
- The tray icon is the app's default window icon converted from RGBA to the
  ARGB32 format expected by StatusNotifierItem.
- If no StatusNotifier host is available, the app still runs but the icon may
  not be shown by the desktop.
- Closing to tray is intentional; quitting is available from the tray menu and
  the in-app Quit action.
- Non-Linux platforms keep the normal close behavior and have no tray in this
  change.
